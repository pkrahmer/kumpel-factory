# The kit

## Description

Every project the factory builds needs the same few files that belong to the factory's contract and not to the project's stack: a pipeline definition, the two forms, the makefile's contract part (the green line and the start facts) and the headings of `CLAUDE.md`. Today each project copies them from `operator/template/`, a Python example, and rewrites what does not fit. After this story the factory holds them once, stack-neutral, as the kit in `operator/kit/`: the pipeline definition of the thin line and of the full line, the forms, `kit.mk` as a file a project's makefile includes, a `README.md` for the project's `factory/` folder and the skeleton of `CLAUDE.md`. The human has worded the files in `planning/kit-draft/`; this story puts them in place unchanged and proves with tests that a project assembled from the kit alone is ready for the factory in everything but what a stack must add: the makefile's own targets and the files under its write paths. `operator/template/` stays as it is; the next story turns it into the Python pack and removes it.

## Interface

- `operator/kit/CLAUDE.md` and `operator/kit/factory/` with `kit.mk`, `pipeline.thin.yml`, `pipeline.full.yml`, `story-form.md`, `feature-form.md` and `README.md`: each a copy, byte for byte, of the file of the same path under `planning/kit-draft/`. Where a guard of this repository asks more of a file (a licence header, for example), the coder adds only that and names it in its entry. No file under `planning/` changes.
- How a project is assembled from the kit, which the tests do in a helper (`tests/support/kit_support.py`) and the guide of a later story describes: the files of `operator/kit/factory/` go to the project's `factory/`, the chosen line's pipeline definition under the name `pipeline.yml` and the other line's not at all; `operator/kit/CLAUDE.md` goes to the root.
- `kit.mk`, as the draft words it: it sets one bash shell per recipe that stops at the first failing line, silences the echo of recipes, makes `check` the default goal, defines `$(start)` and `$(green)`, and the three start facts `facts-diff`, `facts-changes` and `facts-files`, which leave out `factory/` and the pathspecs of `FACTS_LEFT_OUT`, and take the base from `origin/$(WORKING_BRANCH)`, `develop` unless set.
- No module under `src/factory/` changes.
- Tests: `tests/operator_scripts/test_kit_files.py` (the files and the assembled project, through `ProjectCheck`) and `tests/operator_scripts/test_kit_makefile.py` (real runs of make on `kit.mk` in `tmp_path`, with a real local remote for the start facts), with the helper in `tests/support/kit_support.py`.

## Acceptance criteria

1. Both pipeline definitions of the kit load through the pipeline reader: `pipeline.thin.yml` with the roles `builder` and `reviewer` and the stages `doing`, `review`, `approval`, `done`; `pipeline.full.yml` with the seven roles of the full line and an `acceptance_stage`; both say contract `1.2`, name no `make_file`, and hold the comment line `# make_file: factory/Makefile`: rows of one parametrized test.
2. A project assembled from the kit alone, committed, for each line: `ProjectCheck.run` gives no fault for `pipeline definition`, `stage file`, `agents` (the installed agents of this repository's `agents/` folder) and `forms`; `makefile` has the fault `Makefile is missing`; `write paths` has a fault for every write path without a placeholder: rows of one parametrized test.
3. The same project with a root `Makefile` that starts with `include factory/kit.mk` and defines only `sync`, `lint`, `test` and `check`, and with one file under every write path: `ProjectCheck.run` gives no fault at all, for each line.
4. In a makefile that includes `kit.mk`, a recipe written as `$(start)`, a command, `$(green)` prints `<target>: green (<seconds> s)` with the seconds as digits, a dot and one digit; a recipe whose first line fails stops there, prints no green line and make ends red; `make` without a target runs `check`, although `kit.mk`'s own targets come first; the run prints nothing else: no recipe line is echoed.
5. In a clone of a real local remote with a branch that changed one file and added one untracked file: `facts-files` lists the tracked files without those under `factory/`; `facts-changes` names the changed file with its status and the untracked file; `facts-diff` holds the changed file's diff and nothing of a change under `factory/`; the remote's branch is `develop` and `WORKING_BRANCH` is not set, so the base is `origin/develop`.
6. `FACTS_LEFT_OUT=':!build.lock'` leaves `build.lock` out of all three start facts while it is in them without it; with `WORKING_BRANCH=main` and a remote whose branch is `main`, `facts-diff` takes the base from `origin/main`: rows of one parametrized test where they share a setup.
7. A story text that has the five sections of the kit's `story-form.md` in its order passes the factory's form check against that form (`check_story_form`), and one that lacks a section does not.
8. Every kit file equals its draft but for what a guard asked: the test compares each file under `operator/kit/` with a text it holds no copy of, so it checks instead that each of the seven files exists, is not empty, ends with a line end, and holds none of the words `uv`, `gradle`, `pytest`, `cmake` as a word of its own (compared without case); `operator/template/` still exists with its three files.
9. `make check` stays green.
10. docs: a new `operator/kit/README.md` says what the kit is, names each of its files with who owns it afterwards (the kit's files that an upgrade replaces: `kit.mk` and the forms; the project's own: `pipeline.yml`, `CLAUDE.md`, `factory/README.md`), how a project is assembled from it by hand for the thin and for the full line, what the project's makefile must add (`include factory/kit.mk` first, then `sync`, `lint`, `test`, `check`), the two variables of `kit.mk`, and that `factory-check-project` judges the result; `operator/README.md` lists the kit beside the template and says that the template goes with the Python pack; the project guide (`docs/project-guide/operator.md`) names the kit and its tests; `docs/decisions.md` records the three layers (kit, stack pack, starter), who owns which, and that kit and packs live in this repository while starters are repositories of their own (the human, 2026-11-16).

## Smoke test

```bash
uv run python -c "
from factory.pipeline.adapters.pipeline_yaml import RuamelPipelineDefinitionReader as R
for line in ('thin', 'full'):
    d = R().parse(open(f'operator/kit/factory/pipeline.{line}.yml').read())
    print(line, d.contract, len(d.roles), d.make_file)
"
```
Expect: `thin 1.2 2 None` and `full 1.2 7 None`.

```bash
d=$(mktemp -d); trap 'rm -rf "$d"' EXIT
mkdir -p "$d/p/factory"; cp operator/kit/factory/kit.mk "$d/p/factory/"
printf 'include factory/kit.mk\nlint:\n\t$(start)\n\ttrue\n\t$(green)\ncheck: lint\n\techo "check: green"\n' > "$d/p/Makefile"
env -u MAKEFLAGS -u MAKELEVEL -u MFLAGS make -C "$d/p" --no-print-directory | sed 's/([0-9]*\.[0-9] s)/(N s)/'
```
Expect: `lint: green (N s)`, then `check: green`.

```bash
d=$(mktemp -d); trap 'rm -rf "$d"' EXIT
git init -q "$d/p"; mkdir -p "$d/p/src" "$d/p/tests" "$d/p/docs"
cp -r operator/kit/factory "$d/p/factory"; cp operator/kit/CLAUDE.md "$d/p/"
mv "$d/p/factory/pipeline.thin.yml" "$d/p/factory/pipeline.yml"; rm "$d/p/factory/pipeline.full.yml"
git -C "$d/p" add -A; git -C "$d/p" -c user.name=t -c user.email=t@example.com commit -q -m one
uv run python -m factory.entry.check_project --agent-home agents "$d/p"
printf 'include factory/kit.mk\nsync lint test:\n\t$(start)\n\t$(green)\ncheck: lint test\n\techo "check: green"\n' > "$d/p/Makefile"
touch "$d/p/src/a" "$d/p/tests/a" "$d/p/docs/a" "$d/p/README.md"
git -C "$d/p" add -A; git -C "$d/p" -c user.name=t -c user.email=t@example.com commit -q -m two
uv run python -m factory.entry.check_project --agent-home agents "$d/p" | tail -1
```
Expect: first a report with `makefile: FAIL: Makefile is missing`, a `write paths: FAIL: ...` line that names four write paths, the other four points `ok`, and `project: not ready (5 faults)`; then `project: ready`.

```bash
uv run pytest tests/operator_scripts/test_kit_files.py tests/operator_scripts/test_kit_makefile.py
```
Expect: a summary line with only `passed`, no `failed` or `error`.
